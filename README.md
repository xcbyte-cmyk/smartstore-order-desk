# SmartStore Order Desk

스마트스토어 주문 수집부터 발주서 다운로드, 송장 엑셀 송신까지 처리하는 로컬 웹 UI입니다.

[Korea E-commerce Integrated Channel MCP](https://github.com/minwoo19930301/korea-ecommerce-integrated-channel-mcp)를 기반으로 주문 관리 기능을 추가했습니다. 원본 MIT 라이선스와 상품관리 MCP 기능을 유지합니다.

## 주요 기능

| 기능 | 내용 |
| --- | --- |
| 오후 6시 자동 주문 수집 | 토요일~목요일 하루 한 번, 금요일 제외, 수동 수집, 기간 재수집, 상품주문번호 기준 중복 방지 |
| 발주서 다운로드 | 선택 주문의 상품·옵션·수량·수취인·연락처·주소·배송메모를 XLSX로 다운로드 |
| 송장 엑셀 업로드·송신 | 행별 오류 검토, 확인 후 정상 행 송신, 네이버 응답과 실제 반영 상태 구분 |
| 처리 내역 | 수집 결과·다운로드·송신 이력과 확인 필요 주문 표시 |

**주문 UI는 스마트스토어 전용입니다.** 원본 MCP의 쿠팡·11번가·ESM 상품관리 지원과 구분됩니다. 실제 판매자 API 키는 포함되지 않으며, 실계정 수집·발송 성공은 사용자 계정으로 확인해야 합니다.

## Windows 설치

Python 3.11 이상과 Git이 필요합니다.

```powershell
git clone https://github.com/xcbyte-cmyk/smartstore-order-desk.git
cd smartstore-order-desk
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[ui]"
Copy-Item .env.example .env
.venv\Scripts\python.exe -m korea_ecommerce_mcp.orders_web
```

브라우저에서 **http://127.0.0.1:8435** 를 엽니다. 설치 후에는 `start-orderdesk.cmd`를 실행하면 서버를 백그라운드에서 시작하고 화면을 엽니다. 이미 실행 중인 경우 기존 화면을 엽니다. 현재 기본 실행기는 Windows용입니다.

## 사용 순서

1. **스마트스토어 연결**에서 네이버 커머스 API의 Client ID와 Client Secret을 저장합니다. 본인 스토어 SELF 인증이면 판매자 계정 ID는 비워 둡니다. 처음 연결한다면 아래 [인증 정보 준비·저장 방법](#smartstore-connection)을 따라 진행하세요.
2. **지금 주문 수집**으로 첫 주문을 가져옵니다. 첫 수집 범위는 최근 24시간의 변경 내역이며, 이전 기간은 **기간 재수집**을 사용합니다.
3. 주문을 선택하고 **선택 발주서 다운로드**를 누릅니다. 다운로드 자체로 발주 확인이나 주문 상태를 변경하지 않습니다.
4. **송장 업로드·송신**에서 엑셀 양식을 받아 `상품주문번호 / 택배사 / 송장번호`를 입력합니다. 번호는 텍스트 형식으로 유지합니다.
5. 업로드 검토 후 정상 행을 확인하고 송신합니다. 연결 설정에서 **실제 송장 송신 허용**을 켜야 하며, 발주 확인이 끝난 결제완료 일반 택배 주문만 처리합니다.

지원 택배사: CJ대한통운, 한진택배, 로젠택배, 우체국택배, 롯데택배, 경동택배.

## 스마트스토어 연결: Client ID와 Client Secret 저장 방법

### 1. 네이버에서 인증 정보 준비하기

1. [네이버 커머스API센터](https://apicenter.commerce.naver.com/)에 접속해 스토어를 관리하는 계정으로 로그인합니다.
2. **내 스토어 애플리케이션**에서 사용할 애플리케이션을 엽니다. [애플리케이션 관리 바로가기](https://apicenter.commerce.naver.com/ko/member/application/manage/list)
3. 등록된 애플리케이션이 없다면 해당 화면의 안내에 따라 본인 스토어용 애플리케이션을 등록합니다. 사용할 스토어와 **주문 API를 사용할 수 있는 권한·API 그룹**을 확인합니다.
4. 애플리케이션의 **API호출 IP**에 이 프로그램을 실행할 PC가 외부 인터넷에 접속할 때 사용하는 **공인 IP**를 등록하고 저장합니다. `127.0.0.1`이나 공유기 내부의 `192.168.x.x` 주소를 입력하는 것이 아닙니다. 회사 인터넷·VPN·실행 PC의 네트워크가 달라지면 실제 호출 IP도 다시 확인해야 합니다. [네이버의 API호출 IP 등록 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15538)
5. 애플리케이션 상세에서 **애플리케이션 ID**와 **애플리케이션 시크릿**을 확인합니다. 아래 표에 맞춰 프로그램에 입력합니다.

| 네이버 커머스API센터에서 확인할 값 | Order Desk 입력 칸 |
| --- | --- |
| 애플리케이션 ID | **Client ID** |
| 애플리케이션 시크릿 | **Client Secret** |

이 항목의 대응 관계는 [네이버 커머스API 인증 문서](https://apicenter.commerce.naver.com/docs/auth)를 따릅니다. **네이버 로그인 아이디·비밀번호나 네이버 개발자센터의 검색 API용 키를 입력하지 마세요.**

### 2. Order Desk 화면에 저장하기

1. 프로그램을 실행하고 [주문 관리 화면](http://127.0.0.1:8435)을 엽니다.
2. 상단 안내의 **스마트스토어 연결** 또는 왼쪽 아래 **연결 설정**을 누릅니다.
3. **Client ID**에 애플리케이션 ID를 붙여넣습니다.
4. **Client Secret**에 애플리케이션 시크릿을 전체 그대로 붙여넣습니다. 따옴표를 덧붙이지 말고, 앞뒤 공백·줄바꿈이 들어가지 않도록 확인합니다.
5. 본인 스토어용 애플리케이션으로 연결할 때는 **판매자 계정 ID**를 **비워 둡니다.** 이 프로그램이 SELF 인증을 선택합니다. 이 칸은 네이버 로그인 아이디나 스토어 이름을 적는 칸이 아닙니다.
6. 주문 수집과 발주서 다운로드부터 사용할 때는 **이 화면에서 실제 송장 송신 허용**을 체크하지 않아도 됩니다. 실제 송장 송신까지 사용할 때 켭니다.
7. **연결 정보 저장**을 누릅니다. 저장 완료 안내가 나오면 입력 창이 닫힙니다.

입력값은 실행 중인 프로그램 폴더의 `.env`에 저장됩니다. 프로그램이 직접 저장하므로 파일을 따로 편집할 필요는 없습니다. 저장 후 다시 설정을 열면 키 입력란은 비어 있고 **저장된 ID 끝 4자리**만 표시됩니다. 이는 정상이며, 입력란을 비워 둔 채 저장하면 기존 키를 유지합니다.

### 3. 연결 확인 후 첫 주문 수집하기

1. **연결 설정**을 다시 열고 **저장된 연결 확인**을 누릅니다. 이 버튼은 현재 입력 중인 값이 아니라 **이미 저장한 값**으로 확인하므로, 수정했다면 먼저 저장해야 합니다.
2. **API 인증에 성공했습니다.** 메시지를 확인합니다.
3. 설정 창을 닫고 **지금 주문 수집**을 누릅니다. 인증 성공과 주문 조회 권한은 별도이므로 첫 수집 결과까지 확인합니다.
4. 첫 수집은 최근 24시간의 변경 주문을 가져옵니다. 이전 주문은 **기간 재수집**으로 조회합니다.

화면의 **API 정보 저장됨**은 값이 저장되었다는 뜻이며, 실제 인증이나 주문 수집 성공을 뜻하지는 않습니다.

| 상황 | 확인할 내용 |
| --- | --- |
| API 인증 실패 | ID·시크릿이 같은 애플리케이션의 값인지, 시크릿을 빠짐없이 복사했는지 확인합니다. |
| 호출 IP 관련 오류 | 커머스API센터의 API호출 IP와 프로그램 실행 PC의 실제 공인 IP가 같은지 확인합니다. |
| 인증은 되지만 주문 수집 실패 | 애플리케이션의 대상 스토어·주문 API 권한과 화면의 오류 안내를 확인합니다. |
| 수집 성공인데 주문이 0건 | 최근 24시간 내 변경 주문이 있는지 확인하고, 필요한 경우 기간 재수집을 실행합니다. |
| 시크릿을 재발급한 경우 | 새 Client Secret을 입력해 저장하고 다시 연결을 확인합니다. Client ID는 그대로라면 비워 두어도 됩니다. |

시크릿이나 `.env` 파일은 공개 GitHub 이슈·README·스크린샷에 올리지 마세요. 이 저장소는 `.env`를 Git 추적에서 제외합니다.

## 자동 수집과 결과 확인

- 자동 수집: **토요일~목요일 오후 6시(한국 시간)에 하루 한 번**, 금요일 제외. 계정 연결 전에는 대기합니다.
- 브라우저를 닫아도 오후 6시에 서버가 실행 중이면 수집합니다. PC 종료·절전 등으로 놓친 예약은 즉시 재실행하지 않고 다음 지정일 오후 6시에 실행합니다. 필요하면 수동 수집을 이용하세요. 재부팅 후 실행 파일을 다시 열어야 합니다.
- 송신 결과는 **반영 확인 / 성공 응답 후 확인 대기 / 실패 / 결과 미확인**으로 표시합니다. 불확실한 송신을 자동 재시도하지 않습니다.
- API 키, 주문 DB, 로그는 로컬에 저장되며 Git 추적 대상에서 제외됩니다. 공개 웹 서버로 노출하는 용도가 아닙니다.
- 발주서는 범용 주문 목록입니다. 특정 택배사 전용 업로드 서식, 자동 발주 확인, 클레임 처리는 포함되지 않습니다.

자세한 운영 방법은 [주문 UI 안내](docs/ORDERS_UI.md), 원본 상품관리 MCP 설정은 [MCP 설치 가이드](docs/SETUP.md)를 참고하세요.

## 개발 및 검증

```powershell
.venv\Scripts\python.exe -m pip install -e ".[ui,dev]"
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check src tests
```

주문 기능 테스트는 임시 DB와 모의 네이버 응답을 사용합니다. 주문 중복, 페이지 이동, 수집 실패 후 이어받기, 엑셀 번호 보존, 송신 일부 실패, 중복 송신 방지, 자동 수집 실행을 확인합니다. 실계정 테스트와 구분됩니다.
